# 🔑 Keys

## 🔎 Core Concept

- A **key** uniquely identifies an entity instance.
- Most EF Core entities have a single **primary key**.
- An entity can also have one or more **alternate keys**.
- Entities without a key are called **keyless entities**.

```text
Entity
   ↓
Key
   ↓
Unique Identity
   ↓
Identify One Entity Instance
```

---

# 1️⃣ Primary Key

By convention, EF Core configures a property named:

```text
Id
```

or:

```text
<TypeName>Id
```

as the primary key.

### Example

```csharp
public class Car
{
    public string Id { get; set; }
    public string Make { get; set; }
    public string Model { get; set; }
}
```

```csharp
public class Truck
{
    public string TruckId { get; set; }
    public string Make { get; set; }
    public string Model { get; set; }
}
```

### Mental Model

```text
Car
 ↓
Id
 ↓
Primary Key

Truck
 ↓
TruckId
 ↓
Primary Key
```

---

# 🏷️ Configuring a Primary Key

## Data Annotation

```csharp
public class Car
{
    [Key]
    public string LicensePlate { get; set; }

    public string Make { get; set; }
    public string Model { get; set; }
}
```

## Fluent API

```csharp
modelBuilder.Entity<Car>()
    .HasKey(c => c.LicensePlate);
```

> ⭐ **Fluent API can be used when the property does not follow the conventional key naming pattern.**

---

# 🔗 Composite Primary Key

Multiple properties can form a single primary key.

This is called a **composite key**.

```text
State + LicensePlate
        ↓
  Unique Identity
```

## Data Annotation

```csharp
[PrimaryKey(nameof(State), nameof(LicensePlate))]
public class Car
{
    public string State { get; set; }
    public string LicensePlate { get; set; }

    public string Make { get; set; }
    public string Model { get; set; }
}
```

## Fluent API

```csharp
modelBuilder.Entity<Car>()
    .HasKey(c => new
    {
        c.State,
        c.LicensePlate
    });
```

> ⭐ Conventions generally do not infer arbitrary composite keys automatically. Some specific EF Core scenarios, such as owned-type collections, have convention-based composite keys.

---

# ⚙️ Value Generation

For **non-composite numeric and GUID primary keys**, EF Core configures value generation by convention.

### Numeric Key

For example, with SQL Server:

```text
int Primary Key
      ↓
Value Generated by DB
      ↓
IDENTITY
```

### GUID Key

```text
Guid Primary Key
      ↓
EF Core can generate a new GUID
      ↓
Entity Added
```

---

# 🔄 Generated Key Flow

```text
New Entity
    ↓
Key Generated
    ↓
Entity Tracked
    ↓
SaveChanges()
    ↓
Database / EF supplies actual key
    ↓
Entity receives final key value
```

> 💡 When the database generates the value, EF Core can use a temporary value for tracking and then replace it with the actual generated value after `SaveChanges()`.

---

# 🏷️ Primary Key Constraint Name

For relational databases, the default primary key constraint name is:

```text
PK_<EntityTypeName>
```

Example:

```text
PK_Blog
```

You can change it:

```csharp
modelBuilder.Entity<Blog>()
    .HasKey(b => b.BlogId)
    .HasName("PrimaryKey_BlogId");
```

---

# 🧱 Key Types

EF Core allows primitive types such as:

```text
int
string
Guid
byte[]
...
```

as key types.

However:

> ⚠️ Actual key-type support depends on the database provider.

```text
EF Core Key Type
      ↓
Database Provider
      ↓
Supported?
   ┌──┴──┐
  YES    NO
   ↓      ↓
Direct   Conversion /
Mapping  Configuration
```

Some providers may not support every CLR key type directly.

---

# ⚠️ Key Values for New Entities

When adding a new entity, the key value is important.

Common defaults:

```text
int
↓
0

Guid
↓
Guid.Empty
```

If the database generates the key:

```text
Key not supplied
      ↓
EF Core / Database generates value
```

EF Core may use a **temporary value** while tracking the entity.

After `SaveChanges()`:

```text
Temporary Key
      ↓
Database Generated Key
      ↓
Entity Updated with Actual Key
```

---

# 🚨 Generated Key + Manually Assigned Value

Be careful when a key is configured for database generation but you manually assign a non-default value.

Example:

```csharp
var user = new User
{
    Id = 5,
    Name = "Kiran"
};
```

If `Id` is configured as generated:

```text
Generated Key
      +
Manual non-default value
      ↓
EF Core may treat entity as existing
      ↓
UPDATE
```

This can lead to unexpected behavior when you intended an insert.

### Avoid This By

- Turning off value generation when manual key values are intended.
- Explicitly configuring the property to allow manually supplied values where appropriate.

### Example

```csharp
public class User
{
    public int Id { get; set; }
    public string Name { get; set; }
}
```

With SQL Server convention:

```text
int Id
  ↓
IDENTITY
```

Therefore:

```text
Id not supplied
    ↓
INSERT + DB generates Id


Id = 5 supplied
    ↓
EF may treat it as existing
    ↓
UPDATE
```

> ⚠️ **Do not manually assign non-default values to database-generated keys unless that behavior is intentionally configured.**

# 🔀 Alternate Keys

An **alternate key** is an additional unique identifier besides the primary key.

```text
Entity
  │
  ├── Primary Key
  │
  └── Alternate Key
```

An alternate key can also be the **target of a relationship**.

### Example

```text
Blog
 ├── BlogId  → Primary Key
 └── Url     → Alternate Key
```

A dependent can reference:

```text
Post.BlogUrl
      ↓
Blog.Url
```

instead of the primary key.

---

# 🧠 Alternate Key vs Unique Index

```text
Unique Index
   ↓
Enforces uniqueness


Alternate Key
   ↓
Enforces uniqueness
   +
Can be the target of a Foreign Key
```

> ⭐ If you only need uniqueness, use a **unique index**.  
> Use an **alternate key** when the property also needs to be the target of a relationship.

---

# 🔗 Alternate Key as Principal Key

Example:

```csharp
modelBuilder.Entity<Post>()
    .HasOne(p => p.Blog)
    .WithMany(b => b.Posts)
    .HasForeignKey(p => p.BlogUrl)
    .HasPrincipalKey(b => b.Url);
```

```text
Blog
 │
 ├── BlogId
 │     └── Primary Key
 │
 └── Url
       └── Alternate Key
              ▲
              │
              │ FK relationship
              │
Post.BlogUrl ──┘
```

### Important

EF Core can introduce an alternate key automatically when a **non-primary property is configured as the principal key of a relationship**.

---

# 🏷️ Configuring an Alternate Key

## Single Property

```csharp
modelBuilder.Entity<Car>()
    .HasAlternateKey(c => c.LicensePlate);
```

## Composite Alternate Key

```csharp
modelBuilder.Entity<Car>()
    .HasAlternateKey(c => new
    {
        c.State,
        c.LicensePlate
    });
```

```text
State + LicensePlate
        ↓
Composite Alternate Key
        ↓
Unique Identity
```

---

# 🏷️ Alternate Key Constraint Name

By convention:

```text
AK_<EntityTypeName>_<PropertyName>
```

For composite alternate keys, the property names are combined.

Example:

```text
AK_Car_LicensePlate
```

Configure a custom name:

```csharp
modelBuilder.Entity<Car>()
    .HasAlternateKey(c => c.LicensePlate)
    .HasName("AlternateKey_LicensePlate");
```

---

# 🧠 Primary Key vs Alternate Key

| Feature | Primary Key | Alternate Key |
|---|---|---|
| Main entity identity | ✅ Yes | Additional identity |
| Unique | ✅ Yes | ✅ Yes |
| Can be FK target | ✅ Yes | ✅ Yes |
| Usually one per entity | ✅ | Multiple possible |
| Typical purpose | Main identity | Additional unique identity |

---

# ⭐ Key Rules to Remember

```text
1. A key uniquely identifies an entity instance.

2. Id and <EntityName>Id are primary-key conventions.

3. [Key] or HasKey() can explicitly configure a primary key.

4. Multiple properties can form a composite primary key.

5. Non-composite numeric and GUID primary keys get
   value-generation conventions.

6. Database-generated keys can use temporary values while tracking.

7. Be careful when manually assigning non-default values
   to database-generated keys.

8. EF Core supports many primitive key types, but
   provider support varies.

9. Alternate keys provide another unique identifier.

10. Alternate keys can be referenced by foreign keys.

11. If you only need uniqueness, prefer a unique index
    instead of an alternate key.

12. HasPrincipalKey() can make a non-primary property
    the target of a relationship.

13. Alternate keys can be single-property or composite.

14. Primary key and alternate key constraint names
    can be customized with HasName().
```

```text
                         ENTITY
                           │
             ┌─────────────┴─────────────┐
             │                           │
             ▼                           ▼
       PRIMARY KEY                ALTERNATE KEY
             │                           │
       Main Identity              Additional Identity
             │                           │
             └───────────┬───────────────┘
                         │
                         ▼
                  UNIQUE IDENTIFIER


PRIMARY KEY
    ↓
HasKey()
    ↓
Can be Composite


ALTERNATE KEY
    ↓
HasAlternateKey()
    ↓
Can be Composite
    ↓
Can be FK Target


GENERATED KEY
    ↓
Temporary Value
    ↓
SaveChanges()
    ↓

```

> 🎯 **Core takeaway:** A **primary key** identifies the entity's main identity, while an **alternate key** provides another unique identity that can also serve as the target of a foreign key relationship. Be especially careful with **generated key values** when working with disconnected entities or manually assigned IDs.
